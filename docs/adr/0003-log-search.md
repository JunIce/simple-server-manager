# ADR-003: 日志检索采用 grep/sed 式行匹配

## 状态
已接受

## 背景
需要支持历史日志的关键字/正则/时间范围检索。候选：Elasticsearch、SQLite FTS、bleve、grep/sed 式流式行匹配。

## 决策
采用 **grep/sed 式流式行匹配**：日志按行写入文本文件（按大小滚动），检索时按需流式扫描文件，使用关键字 / 正则 / 时间范围过滤，**不引入任何索引**。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|------|------|------|---------|
| Elasticsearch | 功能强、生态全 | 需独立部署、资源重 | 违背轻量常驻定位，且需额外基础设施 |
| SQLite FTS | 轻量 | 非纯 Go（CGO）、并发受限 | CGO 增加交叉编译难度 |
| bleve | 纯 Go、嵌入式 | 索引占用内存、复杂度高 | 简单关键字检索无需索引 |
| grep/sed 式行匹配 | 无索引、无依赖、内存友好、实现简单 | 大文件线性扫描较慢 | **选中** |

## 影响
- 正面：零额外依赖、零索引内存开销，符合轻量常驻定位。
- 负面：历史日志量大时全量扫描耗时，需优化。
- 配套：
  - 日志按大小滚动（rotate），每次检索按时间范围裁剪需扫描的文件集合。
  - `bufio.Scanner` 流式扫描，逐行匹配，命中即返回，支持 `maxResults` 提前终止。
  - 环形缓冲保留最近 N 条，供实时 tail。

## 风险与缓解
- 大文件扫描慢 → 日志滚动 + 时间范围预裁剪 + 命中提前终止。
