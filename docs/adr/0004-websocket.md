# ADR-004: WebSocket 实时通信

## 状态
已接受

## 背景
需要向客户端实时推送日志与指标。候选：轮询、SSE、WebSocket。

## 决策
采用 **WebSocket**（`gorilla/websocket`）实现日志与指标实时推送。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|------|------|------|---------|
| 轮询 | 简单 | 延迟高、浪费资源 | 不满足 <500ms 实时性 |
| SSE | 单向、HTTP 友好 | 仅服务端→客户端、重连语义弱 | 未来需双向控制 |
| WebSocket | 全双工、低延迟、成熟 | 需处理连接生命周期 | **选中** |

## 影响
- 正面：双向通信，日志/指标/未来指令统一走 WS。
- 负面：需处理慢消费者、心跳保活、断连清理。
- 配套：订阅者独立 channel + 丢弃策略防止阻塞。

## 风险与缓解
- 慢消费者拖垮采集 → channel 满丢弃；心跳检测僵尸连接。
