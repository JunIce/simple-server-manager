# ADR-002: 平台适配层抽象

## 状态
已接受

## 背景
当前目标平台为 Windows，但未来可能扩展 Linux/macOS。进程管理、系统服务、资源限制在不同平台间 API 差异巨大。

## 决策
引入 `internal/platform.Platform` 接口，通过 `runtime.GOOS` 工厂选择实现，平台差异封装在实现内部。当前仅实现 Windows，接口保持稳定以支撑未来扩展。

## 备选方案

| 方案 | 优点 | 缺点 | 为何不选 |
|------|------|------|---------|
| 散落 if GOOS 判断 | 实现快 | 上层代码被平台分支污染、难维护 | 不可维护 |
| 构建标签隔离平台文件 | 编译期裁剪 | 仍需统一接口约束 | 作为 platform 内部的补充手段 |
| 统一 Platform 接口 + 工厂 | 上层无平台分支、可测试 | 接口需设计周全 | **选中** |

## 影响
- 正面：core/handlers 层零平台感知，未来扩展平台无需改上层。
- 负面：接口需覆盖多平台能力并集，未实现平台需空实现。
- 配套：Windows 接口测试矩阵。

## 风险与缓解
- 接口能力不足 → 预留 `SetResourceLimits` 等扩展点。
